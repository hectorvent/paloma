# Contributing to Paloma

Thanks for helping. This page covers the workflow; [AGENTS.md](AGENTS.md) covers the
code conventions and [docs/architecture.md](docs/architecture.md) how the tool is built.

## Setup

```sh
git clone https://github.com/hectorvent/paloma && cd paloma
git config core.hooksPath .githooks   # commit-message checks, once per clone
cargo test --workspace                # rust-toolchain.toml pins the toolchain
```

The minimum supported Rust version is the `rust-version` in `Cargo.toml`; CI checks it.

## Branches

Branch off an up-to-date `main` and name the branch `<type>/<short-kebab>`, using the
same types as commits:

```
feat/webhook-listen
fix/send-media-id
docs/scripting-examples
```

## Commits

Versions and `CHANGELOG.md` are generated by [release-plz](https://release-plz.dev) from
commit subjects, so they follow [Conventional Commits](https://www.conventionalcommits.org):

```
type(scope): imperative summary, at most 72 characters

Why the change is needed, wrapped at 72 columns. The diff already says what.

Signed-off-by: Your Name <you@example.com>
```

| Type | Use for | Release |
|------|---------|---------|
| `feat` | A new command, flag or behavior | minor |
| `fix` | A bug fix | patch |
| `perf` | A speed or size improvement | patch |
| `docs` · `refactor` · `test` · `build` · `ci` · `chore` · `style` | Everything else | none |

Add `!` after the type (`feat(send)!: …`) or a `BREAKING CHANGE:` footer for breaking
changes. **Scopes** are a crate (`core`, `config`, `graph`, `manifest`, `cli`), a command
group (`send`, `template`, `webhook`, `flow`, `media`, …), or `deps`, `ci`, `build`,
`xtask`. Leave the scope out when nothing fits.

Keep one logical change per commit. When a command's behavior changes, its page in
`docs/commands/` changes in the same commit.

### Sign-off (DCO)

Every commit needs a `Signed-off-by:` trailer, certifying the
[Developer Certificate of Origin](https://developercertificate.org): you wrote the change
or have the right to submit it under the project's license. `git commit -s` adds it.
Forgot? `git commit --amend --no-edit -s`, or for a whole branch
`git rebase --signoff main`. The hook and CI check the sign-off on every commit.

Maintainers also sign their commits (`git commit -s -S`, GPG or SSH), so tagged releases
trace back to a verified key. Signing your own commits is welcome but not checked.

### No AI attribution

Commit messages and PRs describe the change, not the tools used to make it: no
`Co-Authored-By:` lines for AI assistants and no "Generated with …" footers. The hook and
CI reject them. You are the author and you sign off on the change.

## Before opening a PR

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets
cargo test --workspace
cargo deny check          # when dependencies changed
```

- New or changed commands get a contract test in `crates/paloma-cli/tests/cli/<group>.rs`
  asserting the exit code, what lands on stdout vs stderr, and the exact request body.
- Commands and docs move together: `docs/commands/*.md`, the table in
  `docs/README.md`, and `README.md` when the command list changes.

## Pull requests

- The title is a Conventional Commit subject; it becomes the squash commit on `main`.
- Fill in the template: what, why, and a command a reviewer can run.
- Keep PRs focused. Rebase on `main` rather than merging it in.
- CI must be green: fmt, clippy (pedantic, zero warnings), tests on Linux, macOS and
  Windows, cargo-deny, MSRV, and the commit checks.
